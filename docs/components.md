# Component inventory

What to reuse before building anything new. This is step 1 of **Reuse first** in [CLAUDE.md](../CLAUDE.md), and it applies to specs and plans as much as to code.

**How to check**

1. Find the job below and use the pick.
2. Not listed? Search `src/components/` and the feature's folder under `src/app/` for it: the name you'd give it, its ARIA role (`role="dialog"`, `role="tab"`), or the words on screen ("No open tasks").
3. Close but not quite? Extend it with a prop or variant. Don't fork a copy.
4. Nothing fits? Research it on Mobbin, build it in `src/components/` if it's general-purpose, and add a row here in the same commit.

Paths are under `src/`. Last full sweep: 2026-10-23.

## Overlays

| Job | Use | Notes |
|---|---|---|
| Dialog with a form, or a picker on touch | `components/sheet.tsx` `Sheet`, `SheetTrigger` | React Aria Modal: bottom sheet below `md`, centered dialog from `md`. Esc closes one layer, focus trap, scroll lock, focus returns to the trigger. `title` names it; children may be `({ close }) => …`. `footer` pins the primary under the scrolling body. `size` `md` (512px, the default) or `lg` (672px, the unit and listing sheets); `fullHeight` takes the phone sheet's full height. `dirty`: the backdrop does nothing, and X and Esc call `onDirtyClose` so the owner can ask first (without it they close, discarding a one-field sheet's value). `surface="public"` puts the dark public tokens on the overlay. While open it keeps `--kb-inset` current (`useKeyboardInset`), so the phone sheet and the tablet dialog sit above the on-screen keyboard with the footer on it. `layout="palette"` is typed for the command palette and renders as a sheet until that's built |
| A picker or a step inside a sheet | `components/sheet.tsx` `SheetView`, `useSheet` | Never a sheet on a sheet. Inside a `Sheet` (check `useSheet()`), render the picker's body in a `SheetView`: while mounted it takes the sheet's title, body and (with `footer`) footer, and a back arrow sits beside the X; unmount it to go back. The sheet's own body stays mounted, and comes back at its scroll with focus on what opened the view. `escape="back"` (the default) goes back one view on Esc, for a picker over a form; `"close"` closes the layer the step belongs to with nothing changed, for a step that answers one pick (a status follow-up, Custom repeat, the phone calendar): the picker's own view under it leaves too and the form shows again, and with no picker under it the sheet closes (`escapePlan`). Children render through React Aria's `Overlay` portal, so they keep their own state and a button in the view isn't also the trigger's |
| Confirm (destructive, or "discard changes?") | `components/confirm-dialog.tsx` `ConfirmDialog` | React Aria modal like `Sheet`: portals to `<body>`, Esc and a backdrop click close it, focus is trapped and returns to the trigger, the page doesn't scroll. Render it while it shows; `onClose` is every way out. The title names the object; `body` is one sentence of consequence, optional when the title is the whole question. It draws Cancel itself (`cancelLabel`, "Cancel" by default) with an Esc keycap for a mouse; `actions` is the rest, primary last: a `destructive` `Button` naming what goes ("Delete task"). `busy` holds it open while the action runs. Below `sm` the actions stack full width, primary on top, however many there are |
| Ask before an in-app link leaves work behind | `components/leave-guard.tsx` `LeaveGuard`, `useHoldLeave`, `useLeaveGuard` | Wrap the page in `LeaveGuard`; whatever knows calls `useHoldLeave({ title, stay })` while it matters. `BackLink` inside, or any link that leaves through `useLeaveGuard()`, then asks in a `Sheet` with just the title: "Leave anyway" and `stay` as the main button. Closes by itself, and stays, once the hold lifts. The contractor job page holds it while photos upload. A Sign out button calls `useLeaveGuard({ signOut: true })` (the app's and the portal's account menus do). Reloads and closed tabs are `useLeaveWarning`'s; browser Back isn't caught |
| Photo and video viewer | `components/lightbox.tsx` `Lightbox` | Dark photo stage (`--photo-stage`), "3 / 11", arrows, arrow keys and swipe, Download, who added it and when. Videos play inline. `onDelete` (staff) adds Delete, confirmed in a `Sheet` on top. `MediaGrid` opens it |
| Mobile nav drawer | `components/app-shell.tsx` `AppShell` | Built into the shell below `lg`, on `--canvas` at the Overlay level; Esc closes. It scrolls when the screen is short, and every control in it is 44px on touch |
| Popover with a mouse, Sheet on touch | `components/picker-layer.tsx` `PickerLayer`; `components/use-coarse-pointer.ts` `pickContainer`, `useCoarsePointer` | `PickerLayer` is the layer every picker opens: an anchored popover with a mouse and on a touch tablet (selectors 4.2 A, touch rows), a titled bottom sheet on a touch phone, and, when the picker already sits in a sheet, a `SheetView` in it with a back arrow, never a second sheet. Trigger and layer share one `DialogTrigger`; with no `trigger` and an `anchorRef` the caller opens it (a field with two ways in). A closed trigger opens on Down or Up as well as Enter and Space (`openOnArrow`, added to the trigger for you; a button that opens a trigger-less layer spreads it itself). `pickContainer()` reads the screen when the layer opens, so a tap before hydration can't open the desktop popover on a phone, and the choice is held until the layer has closed, so a phone's sheet slides out. `useCoarsePointer` is the same test as Tailwind's `pointer-coarse:`, false until hydrated; layout that changes what's on screen stays CSS (`pointer-coarse:`) so nothing flashes |
| Keep a layer above the on-screen keyboard | `components/use-keyboard-inset.ts` `useKeyboardInset` | Sets `--kb-inset` on the root from `visualViewport` ("0px" with no keyboard) while mounted, and returns it; use `bottom: var(--kb-inset, 0px)`. `Sheet` calls it while open. `app/(app)/layout.tsx` exports `viewport.interactiveWidget: "resizes-content"`, so Android Chrome resizes the page itself and the hook reads 0 there; iOS needs the hook. Not in the root layout, so the portal's fixed bar and the public site keep the default |

## Known gaps

Jobs nothing covers yet, and holes in the picks. The first feature that needs one does the Mobbin research, builds it in `src/components/`, and adds a row above.

- **Form field layout.** No shared label, helper text and error wrapper.
- **Tap targets.** The primitives are 44px on touch now. Raw `<button>`s and fields outside `ui.tsx` (filter bars at `h-8`, text links in tables) still warn; move them onto the primitives.
- **Old popovers.** `GlobalSearch` predates `Popover` and wires its own outside click; move it onto it when touched.
- **Inline text edit.** Exists only as feature copies (Duplicates). Extract on the next touch.
- **Sticky headers on wide tables.** A table wider than its column scrolls sideways in its own box, and a header can't stick to the page from inside a scroll container, so there `Th` scrolls away with the page. Sticking it needs a header synced to the box's scroll.
- **Loading state.** `Spinner` and `Button` `pending` exist. The first skeleton is the Financials Overview's `(overview)/loading.tsx` (labels drawn at once, static `--fill-1` blocks at figure height, `MonthBarsSkeleton`): copy its pattern, in the route's own group so sibling tabs don't borrow its shape. Older pending actions still relabel.
